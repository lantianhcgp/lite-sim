fix: 候选词溢出方框 + 图标圆角裁切（对齐真机）

用户两个反馈：
1.「候选词没在它的框里面」
2.「键盘上的图标应该是圆角裁切的，我真机是这样的」

根因 1 — CSS 单位前的空格让整条声明失效：
  hml 写 `width : {{ chipW }} px` → 求值成 `width : 74 px`
  （数字与单位间有空格）——浏览器 CSS 视为**无效声明整条丢弃**，
  于是回退到 .im-candidate-text 类里的硬编码 width:54px;
  font-size:38px。EN 模式本该是 chipW=74 / chipFont=24，
  54 宽 + 38px 字号下 `might`(约55px) 必然溢出 → 「不在框里」。
  修：fixCssUnits() 把 `74 px` 规范化成 `74px`，
      cssTextToInline 与元素 style 求值后都过一遍。
  实测：width/font 恢复为 (74, 24) ✓

根因 2 — 浏览器 border-radius 不裁子元素：
  真机 Lite 中带 border-radius 的容器会把溢出的子内容按圆角裁掉，
  浏览器必须显式 overflow:hidden。
  修：最终 style 合并后，若含 border-radius 且无真 overflow → 补 hidden。
  两个坑：
  a) 必须放在「类 CSS + 元素 style」合并**之后** —— 图标容器
     (hml line 18/28/85/89) 没有 class，border-radius 只在 style
     属性里，放早了漏 4 个（实测）；
  b) 检测别被 `text-overflow:ellipsis` 骗了（它含 "overflow:"），
     用 lookbehind `(?<![-a-z])overflow`。
  实测：30/30 含 border-radius 的 div 全部有 overflow:hidden ✓

顺带修 parseAttrs 布尔属性正则：
  `/(?:^|\s)([\w-]*)(?=\s|$)/` 不跳过引号内容，把 style 值内部的
  width/font-size/color... 误判成布尔属性（DOM 出现 chipw="true" 等脏
  属性）。改为先剥离 `attr="..."` 与引号串再匹配。

回归：checker 30/30、moduleloader 9/9、全项目加载失败 0、
      smoke 6/6、journey 25/25、拼音 7/7
