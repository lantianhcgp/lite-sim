fix: 拼音候选词链路 7/7 通过（词典 seed + file.get 死循环）

用户报「切到拼音后点拼音不出候选词，实时显示的是英文字母，真机正常」。
逐层取证（dump img 状态 → MCP 读日志 → 运行时源码反查 → 拆解最小复现）
定位到 5 个独立问题，全部修复：

1. **file.get 返回值错 → readLargeFile 死循环（页面挂死 2.5 分钟）**
   Lite 的 file.get 取的是「文件元信息」{length}，common/fs.js 的
   readLargeFile 靠 data.length 算分块数。我的 mock 走了 simRead 返回
   {text,offset,remaining} → data.length=undefined → read_count=NaN →
   `idx >= NaN` 永远 false → step() 无限递归。
   → get 改为返回 {uri, length}；readText 才返回内容分块

2. **词典没进 file mock**
   keyboard 页读 internal://app/rawfile/inputMethod/chineseCandidate.json
   （26KB），mock 空 → 301 → chineseCandidateData=[] → 候选词永远为空。
   → server 的 /api/source 附带 resources/rawfile/*（json/txt），
   app.js 存 pendingRawfile 并 seed（3 个常见 uri 前缀都写）

3. **seed 时机错 → 模块缓存固化空词典**
   inputMethod.js 模块顶层就调 loadCnDict()，seed 若在其后，
   读到 301 后模块缓存不再重读。
   → seed 放 loadProject 末尾（任何 runPage 之前）

4. **切换按钮找不到**
   切换按钮是 <input value="{{inputMethod.keyboardType}}">
   （不在 .nav-btn/.im-key 里）→ 测试选择器补 input

5. **测试词本身不存在**：词典 d['n'] 无 'ihao' 组合（get('nihao')→0），
   改用 'ni'（22 候选）。这是数据事实，不是 bug。
